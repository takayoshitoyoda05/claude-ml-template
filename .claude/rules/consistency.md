## 記述と実装の整合

- ある挙動を説明する記述(README・エージェント定義・スキル・手順書・docstring)を
  書いたら、その挙動の実装・設定・他のドキュメントを grep で確認する
- 確認に使ったコマンドと結果を完了報告に含める
- 食い違いを見つけたが自分の担当ファイルの外にある場合、勝手に直さずに報告する
  (最小diff規律を優先する)

## 対になるファイルの整合

- 対になるファイル(`verify-hooks.sh` / `.ps1`、`claude-init.*` / `claude-update.*`、
  sh 版 / PowerShell 版)の片方を変更したら、必ず対応する側も確認する
- 片方だけを変更してよいのは、対応する側に同じ変更が不要だと確認できた場合だけ。
  その理由を完了報告に書く
- 1対1対応を機械的に検証したコマンドと結果を完了報告に含める。標準形:

  ```bash
  diff <(grep -oE '"<マーカー>: [^"]+"' a.sh | sort -u) \
       <(grep -oE '"<マーカー>: [^"]+"' b.ps1 | sort -u)
  ```

  件数(生・一意)と diff の3点を報告する(件数を見ないと重複で数が合ってしまう)
