# handoff 推奨モニタの指標堅牢化(発散 v1)

日付: 2026-08-20
文脈: 案A(auto-compact 閾値の引き下げ)+案C(Stop フックの handoff 推奨モニタ)を
実装する方針。C の弱点「transcript サイズという代理指標が粗い」を解決する
アイデアの発散。絞り込みは design-interview で行う。

## 発散した案

### G1: 指標の精密化系(代理指標をやめる)
1. **transcript JSONL の usage 直読み**: Stop フックは payload の transcript_path を
   受け取れる(checkpoint_before_compact.py が前例)。transcript の assistant
   エントリの usage(input_tokens + cache_read_input_tokens)の末尾1件を読めば
   現在のコンテキスト使用量がほぼ正確に取れる可能性が高い。**要実物検証**。
2. **statusline を計測器化**: statusline スクリプトが受け取る context 情報を
   ファイルに書き出し、Stop フックはそれを読む。案B(可視化)と計測経路を共有。

### G2: 圧縮イベント活用系(確実なシグナルに乗り換える)
3. **auto-compact 回数カウント**: PreCompact フック(matcher: auto)で発生回数を
   記録。「同一セッション2回目の自動圧縮」は要約の要約化が始まった確実な劣化
   シグナルで誤判定がほぼない。ただし compact 前の予防はできない。
4. **G1+G2 の複合**: 平常時は usage 実測でウォーターマーク判定、compact 発生後は
   回数基準に切り替え(圧縮直後は使用量が下がるためサイズ指標が「回復」と誤認する)。

### G3: 警告設計系(オオカミ少年化の防止)
5. **ウォーターマーク3段階**(low/high/critical)で二値判定をやめる。
6. **バーンレート**: 絶対量でなく直近Nターンの増加速度を見る。
7. **複数窓**: 「高い」AND「増え続けている」の両立時のみ警告(スパイク除外)。
8. **重複排除**: 一度警告したら使用量が +10% 増えるまで再警告しない。
9. **行動つき警告を1回だけ**: 「handoffして、と入力」「session_state.md は最新」
   のように次の1手と根拠を添える。
10. **区切り連動**: ml-pipeline 手順9 や evaluator PASS 等の区切りイベント直後
    だけ警告(作業途中の「今すぐ切れ」を避ける)。

### G4: 警告不要化系(自動化の極端化)
11. **常時記録の充実**: record_session_state.py を handoff 文書相当まで充実させ、
    警告なしで「重くなったら新セッションで再開」を標準動線にする。
12. **fail-closed 強制**: critical 到達で Stop を exit 2 ブロックし handoff 文書
    作成を強制(enforce_eval 思想。誤発火の被害が大きい諸刃)。
13. **時間ベースのみ**: セッション開始から N 時間で提案(数行で済むが粗い)。

## 次のステップ
- G1-1 の前提(transcript に usage があるか)は実物の transcript で数分で
  検証できる。方向性を選ぶ前にこれだけ先に潰すと判断が楽になる。
- 方向性を選んだら design-interview で仕様を固める(閾値・警告文・
  CLAUDE_* フラグ名・既存フックとの責務分担)。
